## 具体问题与纠正

### 01 购买人群口径
- `orders` 到 `order_items` 一对多。对原始商品明细直接 `COUNT(*)` 会夸大订单次数。
- 用户标识采用 `customer_unique_id` 而非 `customer_id`。
- 与原 RFM 记录一致，要求订单有商品明细；但与直接基于 `orders` 的部分旧 Cohort 查询不一定完全一致。
- 如果与既有看板 94,983 / 2,887 不同，应优先查统计口径，**不要反过来修改 SQL 使结果迎合截图**。

### 02 Cohort 时间截断
- 原始 SQL 仅对存在活跃购买的月份返回行，界面空白无法明确区分：没有人买 vs. 没到观察时间。
- 新 SQL 为每个 Cohort 生成 M0–M6 的*可观察*网格，已观察而没有人回购显示 0，未成熟月份不显示。
- `customer_month` 去重；自然月是对齐后的月初日期，用 `TIMESTAMPDIFF(MONTH,...)` 计算间隔。
- 保守排除样本最后出现的月份（不代表其他月份已经证明数据完整）。可能影响与旧截图的一致性。
- 该指标更准确叫「自然月回购率」，不能等同订阅产品的逐月连续留存率。

### 03 履约评分的样本完整性
- 源笔记将 `COUNT(DISTINCT order_id)` 写作 `reviewed_order_count`，在 `LEFT JOIN` 包含无评价订单时名称具有误导性。
- 现在分开输出 `delivered_order_count` 和 `reviewed_order_count`，并暴露无评分占比；均值只基于有评分订单。
- 同订单若多条评价，先取订单均值再计入分组，不让评价行数直接放大权重。
- 仍需核查每组评价覆盖率、不同延迟分组数量、评分尾部异常；不能说「物流导致差评」或「物流导致复购低」。
