# Olist 求职作品集：可证明的成果清单（Evidence Inventory）

**日期：2026-11-02**  
**来源**：早期 Olist 项目聊天记录、《数据检查.md》原始 SQL 笔记、现有 Power BI 四页看板及本仓库代码。  
**用途**：确定作品集中应保留的成果和技术证据。它是**候选内容审核表**，不是将未核验数据直接上线的许可。

## A. 三项最具招聘价值的能力成果

### A1. 数据粒度与指标口径（推荐作为技术亮点）
- 证据：9 张业务表、`customer_unique_id` 去重用户；核查 `order_items` 同订单多行、`order_reviews` 同订单多行、geolocation 同邮编前缀多行。
- 具体方案：商品金额 `SUM(order_items.price)`；订单数使用 `COUNT(DISTINCT order_id)`；卖家指标先聚合 `order_reviews` 到订单级，再取 `DISTINCT seller_id, order_id`，筛选 >=20 笔有效订单后排名。
- 技术：MySQL CTE、窗口函数（累计、移动均值、贡献占比、排名）、订单级去重、异常和缺失检查、索引语句。
- 证明：能够控制多表 join 带来的统计膨胀、划清“用户 / 订单 / 订单明细 / 卖家”粒度。
- 不能写：任何没跑过的性能优化倍数、全流程自动化建模、生产级数据治理。

### A2. 历史复购与人群分层（推荐作为首要业务发现）
- 看板数字：购买用户 94,983、历史重复购买用户 2,887、历史复购 3.04%、只购买一次 96.96%。
- 方法：按真实用户去重并统计至少 2 笔有效订单；按首购月份构造 Cohort 月度回购；RFM 的 R/F/M 和历史客单额分群。
- 业务表达：「历史样本中重复购买用户占比较小，值得进一步研究首购后二次购买机会。」
- 限制：历史复购率 ≠ 流失率；不同首购月份观察窗口不齐；F=1 占 96.96%，RFM 频次维度区分力有限。
- 核验：确认订单状态和截止日期、计算 Cohort 成熟窗口、修复并复跑原 SQL 笔记中的 CTE / 拼写问题；不能声称预测流失。

### A3. 物流履约与客户体验（推荐作为第二业务发现）
- 看板数字：准时送达率 93.23%；总体评分约 4.09/5；提前送达平均评分约 4.29，按时 4.04，延迟 1–3 天 3.29，延迟 4–7 天 2.11，延迟 8+ 天 1.70。
- 方法：`DATEDIFF(order_delivered_customer_date, order_estimated_delivery_date)`；5 档时效分组；订单级平均评价；卖家-订单去重并设置至少 20 笔的样本门槛。
- 业务表达：「在历史订单中，严重延迟组评分明显低于提前/准时组，值得进一步诊断延迟来源及异常卖家。」
- 限制：必须公开各组订单数与有效评价数；原笔记里的 `reviewed_order_count` 采用全部订单数而不是非空评分的真实评价样本数，字段命名可能误导；仅说明相关不能断言因果。
- 核验：检查截止和妥投条件、每组评价缺失率、评分统计口径与卖家排序样本量。

## B. 作为支撑而非首屏主角的成果

**经营及收入：** 商品 GMV 看板约 R$13.49M，需明确按有效订单中的商品价格求和，不等于支付金额与运费；月度环比、累计 GMV、三月移动均值、品类贡献、州级分布与支付方式均有对应的 SQL/BI 产物。经营分析能证明 SQL 覆盖度，但单独不足以构成最强业务故事。

**探索工作：** 历史聊天记录出现过 8 张 Python 图和 7 份 EDA CSV、FineBI 探索、27 州 GeoJSON 整理和 BI 最终迁移；这些体现实际探索广度，但首页不应重复堆叠工具和图表。

**BI 成果：** 已提交四张真实截图、原始 PBIX（约 32.3 MB）和四页 PDF。网页图片切换、放大、下载正常属于作品集呈现能力；不能假装网页截图支持 Power BI 自身的交叉筛选。

## D. 拟用于网页的精简文案（仅在 P0 数据核验后发布）

**发现 1：用户重复购买**  
「94,983 名历史购买用户中，仅 2,887 名购买至少两次（3.04%）。从购买频次到 Cohort 和 RFM，重点研究首购后的再次购买机会。」

**发现 2：履约与评分**  
「订单配送越偏离预计日期，客户评分的分组均值越低：提前送达约 4.29，延迟 8 天及以上约 1.70。建议优先排查严重延迟订单及对应卖家。」

**技术证据（简短）**  
「基于 9 张关联表建立 MySQL 分析口径；对订单明细、评价与卖家订单先按业务粒度去重，再计算 GMV、复购和履约指标。」

不把第二条关联发现写成「延迟导致差评」，不把第一条历史复购率写成「流失率」。案例中的策略属于建议而非已实施成果。
