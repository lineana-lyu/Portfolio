# CR-001 · 内容减法（SDD 需求变更）
日期：2026-11-02 | 状态：用户已明确要求执行

## 为什么变
M1 的「五步导航 + 双指标卡 + 每步证据/结论/下一步」虽然有逻辑，但访客需要反复点击、阅读大量高度模板化文字才能理解项目；内容和交互在重复同一条线索，更像 AI 生成的标准分析流程，降低招聘方评估效率。

## 覆盖 SPEC v1.0 的位置
- **替换 S01 视觉表达**：由「标题 + 两个并列指标卡」改为「一个最重要的事实：96.96% 仅购买一次」，在同一段交代 94,983 人中 2,887 人多次购买。指标口径仍须 SQL 对账。
- **替换 S02 UI 形式**：去除五个可点击节点和导航，压缩成连续可读的三个真实判断：①用 customer_unique_id 而非明细行计数；②用 Cohort 检查新用户观察时长；③指出 RFM 在 F=1 集中时难以有效细分，转向运营实验假设。
- **替换 FR-02**：无需交互即可浏览完整分析主线，3 条判断直接可见；唯一折叠区域为「口径与局限」。
- **替换 FR-09**：禁止重复大 KPI、重复描述和开发状态标签；仍保留数据证据不足、边界条件和策略未实施的说明。
- **M1 不再要求 JavaScript**：使用原生 HTML details 展开附注，删除原五步交互脚本；无障碍验收检查键盘可达的展开控件。

## 保持不变
- 核心研究问题仍是「是否存在值得验证的二次购买机会」。
- 不得把历史复购率当作流失概率；不得把 GMV 变化归因为新客；不得把策略建议写成实施成果。
- M2 必须提供真实 SQL 对账与 Cohort 成熟窗口校验；M3 原生 Power BI 嵌入，不重绘大屏。
- GitHub main 保存所有变更，review 留存每次审查。

## 验收
1. 桌面 1440×900 首屏直接看到事实和分析判断；移动 375px 无横向溢出。
2. 一眼看懂最重要发现，分析只保留三条不可删的论证，结论不超出证据。
3. 原生 details 可用，GitHub 链接真实；不出现旧 tab 系统或 JS 运行错误。
4. **不等于最终上线通过**：原生 Power BI 嵌入和 SQL 证据仍是阻断项。

## 批判性取舍
减少点击 ≠ 减少分析严谨性。将限制条件折叠，是为了减少初读认知负担；没有证据支持的结论仍需降级，不以「简洁」为借口掩盖不确定性。
