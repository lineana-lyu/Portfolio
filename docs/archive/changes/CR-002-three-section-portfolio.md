# CR-002｜改为三段式求职展示页

**日期：** 2026-11-02  
**状态：** 已获得用户同意，替代 CR-001 的页面信息架构。

## 变更原因
旧版本过度聚焦「96.96% 只购买一次」和冗长的分析推演，未客观呈现 Olist 四页 Power BI 的业务范围。用户明确要求：**只介绍项目背景、说明分析路径、直接展示原生 Power BI 大屏**。网页不重复分析报告，不重绘 BI 图表。

## 新的信息架构
1. 项目背景：标题、数据来源、业务任务、技术工具，一段话讲清楚。
2. 分析路径：先了解经营规模与收入结构，再分别研究用户行为与履约体验。每一主题只显示业务问题 + 关键指标方法；不把四项分析写成因果链。
3. Power BI 报表：一个原生 iframe 展示位，由 Power BI 报表自带的页签和筛选处理交互；有真正公开嵌入 URL 才加载，否则显示准确的未接入状态。

## 明确删除
- 独立的复购核心结论及其 KPI 大字、三条长推导、策略卡、方法折叠区。
- 五步分析演示、额外图表、网页复刻 Power BI 的筛选器。
- 任何不支持的「已验证」「预测流失」「增长来自新客」「物流导致差评」断言。

## 仍然需要保证
- 四主题是**阅读顺序/分析组织**，不是已证实的因果关系。
- Power BI 原生嵌入必须有公开 URL，未完成不能冒充成功。
- 源 SQL 的口径问题、Cohort 不完整观察期、配送评分相关性仍列入开发审计，不在展示页复制长篇解释。
- GitHub main 为代码来源；每次变更要有验收及复盘记录。

## 验收
- [ ] 桌面和移动端均能在一页中快速识别三段内容，整页不再有重复 KPI。
- [ ] 四个分析主题各有一个清楚的业务问题。
- [ ] 报表区域使用真正的 Power BI iframe 或明确说明未接入。
- [ ] 基本链接、键盘和布局可正常使用。
- [ ] 代码已进入 GitHub，审查记录与事实状态一致。
