# SDD-03｜M1 内容减法后的批判性复审

日期：2026-11-02  
对应变更：[CR-001](../changes/CR-001-content-reduction.md) ｜规格：[SPEC v1.1](../SPEC.md)

## 审查结论
**内容结构 GO；对外招聘发布 NO-GO。** 用户明确指出旧版本「像 AI 生成的套路」：此轮删掉通用五步导航，改为一个事实、三个可被证伪的判断和一个未实施的运营实验。

## 具体删掉了什么
- **五步 Tab 导航**及整块动态证据/下一步说明：浏览主线不需要任何点击，删除旧 `app.js`。
- **两个并列大指标卡**：主标题只突出「96.96% 一次购」，其余样本数放进一句话。
- **M1 / 数据待复核等页眉开发标签**：开发状态保留在仓库，不拿内部过程占据招聘方首屏（数据未核验仍在页面小字注明）。
- **重复的英语栏目和套路化解释**：仅保留「我怎么判断这件事」和最小三条分析判断。
- 不追加任何地图、重复图表、动画、强制交互或空 Power BI iframe。

## 这三条内容为什么值得留下
1. **真实 SQL 决策**：customer_unique_id 和去重订单，避免把订单明细行误当「购买次数」。可应对面试官追问。
2. **时间偏差警惕**：一次购是否来自观察窗口不成熟，需 Cohort 成熟窗口校验。这是结论可信度的必要条件。
3. **主动拒绝不合适的方法依赖**：F=1 高度集中，不能单凭 RFM 标签做「流失运营」。明确提出后续验证人群细分和 A/B 增量效果。

## 仍然不合格的地方
- **P0：数据证据缺失**。96.96%、94,983、2,887 仍来自既有截图，缺少同口径 SQL 复现结果；不能认为已验证。
- **P0：Cohort 成熟窗口尚未核实**。当前只能说「现有看板显示多数后续月份回购比例较小」，不能直接推断原因。
- **P0：没有原生 Power BI 公开嵌入**。网页是案例说明，不是最终可核验证据的完整作品集。
- **P1：商业建议仍为假设**。为何「优惠券」不一定优先、触达分组如何设计、成本收益是否合理，需之后补实证或实验计划。
- **P1：目前主要展示用户分析**。履约主题不强行塞回首屏，需在后续证据模块以独立侧证形式呈现，不要构建虚假因果链。

## 实测
- Playwright/Chromium：1440×900 与 375×812 正常渲染；无横向溢出、JS 错误。
- 仅一个 H1、三条分析理由、一个原生 details；展开说明操作通过。
- `index.html` 和 `styles.css` 无 JavaScript 依赖；键盘可使用原生链接、details。
- 这是在本地生成的文件上完成的检查；提交后需继续对账远端 blob 和本地代码以避免版本偏差。

## 审核意见
若我是 HR，我比旧版更快抓住「96.96% 一次购」及具体分析取舍，整体不像通用 BI 宣传页。但它**仍只是一份精简的论证摘要**。如果下一轮不补 SQL / 真实 Power BI，继续优化字体、阴影和措辞对求职价值帮助有限。
