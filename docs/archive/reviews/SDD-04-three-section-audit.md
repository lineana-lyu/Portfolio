# SDD-04｜三段式作品集重构审查

日期：2026-11-02  
规格：[SPEC v2.0](../SPEC.md) ｜变更依据：[CR-002](../changes/CR-002-three-section-portfolio.md)  
审查对象：`index.html`、`styles.css`、`embed.js`、`README.md` 及冒烟测试。

## 总结
**内容结构 GO；公共发布 NO-GO。** 当前不是完成的 Power BI 在线作品集：公开嵌入 URL 未提供，且没有进行真实浏览器／匿名访客验收。

## 逐模块批判性审查

| 模块 | 必须存在的价值 | 减法判断 | 结果 |
|---|---|---|---|
| 01 项目背景 | 让访客迅速知道数据、工具和业务范围 | 保留 1 段介绍，不再以「96.96% 一次购」主导整个四主题项目；删除核心 KPI 大卡 | **通过（内容）** |
| 02 分析路径 | 解释四页 Power BI 为什么按这样的业务问题组织 | 每主题仅一项业务追问与一行方法。路径「经营→收入」后拆出用户与履约两个独立问题，不暗示因果链 | **通过（内容）** |
| 03 原生 Power BI | 让访客直接体验已有的完整报表 | 仅一个 iframe；不重复开发 ECharts、网页过滤器、图表或 PDF 长文 | **容器已做，实际嵌入待完成** |

## 已删除（对招聘方无必要的信息）
- 旧版三项用户分析判断、RFM 局限的整屏解释、二次购买运营建议卡。
- 抢夺注意力的复购大 KPI 与冗余故事化语言。
- 虚假的「分析流程点击交互」及 Power BI 自研替身看板。
- 不必要的时间/业务量数值，保留到 Power BI 原生图表中展示。

## 工程审查

通过 GitHub 远端文件读取并逐条断言，共 10 条静态检查通过：
1. 3 个 main 下的 section；
2. 4 个业务分析主题；
3. 无旧版长篇叙事；
4. 仅 1 个 iframe；
5. 无截图冒充交互报表，空链接提示准确；
6. `embed.js` 限制为 `https://app.powerbi.com/view?r=...`；
7. 当前嵌入 URL 为空，展示位状态真实；
8. CSS 存在桌面与移动端布局规则；
9. 内容与 SPEC v2.0 一致；
10. 冒烟测试已替换旧版断言。

### 还未通过
- **浏览器渲染：** 当前工具环境无法从 GitHub 直接下载网页文件到本地测试容器，故未运行 Playwright 来验证最终渲染／手机溢出。仓库中的 `tests/m1_smoke.py` 可供克隆后执行，不能把未运行测试写成通过。
- **Power BI：** 尚无 Publish to web 公开链接，无法测试未登录访客的页签、地图、筛选；报表语义模型的公开安全检查未完成。
- **报表一致性：** 待确认四页是否属于同一个发布到 Power BI Service 的报表。若是独立报表，则需调整嵌入约定，不可把其中一页冒充四页。
- **业务口径：** SQL 对账、Cohort 观察窗口、配送评分样本量仍是作品集发布质量门槛，暂不在首页扩写。

## 招聘方角度的评语

**更像一个作品集入口，而不是 AI 套话拼贴。** 背景说明项目边界，路径只帮助访客阅读报表，关键业务结论留在 Power BI 中。无需先读大量文字或点击伪交互。

但最终质量强依赖 Power BI 实际可访问、图表内容清楚。若报表不能公开正常打开，网站仍不能证明项目的分析能力。

**结论：允许继续集成 Power BI，暂不宣称完成/可投递。**
